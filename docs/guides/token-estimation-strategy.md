# Token估算策略文档

## 📋 文档概述

本文档定义了多语言翻译场景下，如何估算AI模型（Gemini、OpenAI等）的`maxOutputTokens`参数。

**核心目标**：
- 防止翻译结果被截断
- 避免浪费Token配额
- 支持任意语言对互译
- 代码简单易维护

---

## 🎯 方案核心思想

**把所有语言都换算成"英文单词"这个通用基准，再转换成目标语言的Token数**

类比：就像货币兑换
```
人民币 → 美元（国际通用货币） → 欧元
源语言 → 英文单词数（通用基准） → 目标语言Token
```

**为什么选择英文作为基准？**
1. YouTube平台以英文字幕为主
2. 大部分Token研究以英文为基准
3. 英文单词是清晰的计量单位

## 🔄 计算流程（5步法）

### 步骤1: 估算"英文等价单词数"

**目标**：把任意语言的输入文本换算成"如果用英文表达需要多少个单词"

#### 情况A：输入本身是英文
```
英文等价单词数 = 直接统计空格分隔的单词数
```

**示例**：
- 输入："Hello world this is a test"
- 英文等价单词数 = 5

#### 情况B：输入是其他语言
```
英文等价单词数 = 源语言单词数 ÷ 源语言缩放比例
```

**示例1（中文输入）**：
- 输入："我爱你中国" = 10个字符
- 中文单词数 = 10 ÷ 2 = 5个中文词（中文按2个字符≈1词估算）
- 中文缩放比例 = 0.5（表1查询）
- 英文等价 = 5 ÷ 0.5 = **10个英文词**

**解读**：5个中文词的信息量，用英文需要10个词表达

**示例2（日语输入）**：
- 输入："ありがとうございます" = 10个字符
- 日语单词数 = 10 ÷ 2.5 = 4个日语词
- 日语缩放比例 = 0.6（表1查询）
- 英文等价 = 4 ÷ 0.6 = **6.67个英文词**

#### 单词计数规则

| 语言类型 | 计数方法 | 示例 |
|---------|---------|------|
| 空格分隔语言<br>（英语、欧洲语言） | 按空格分割计数 | "Hello world" = 2词 |
| 中文 | 字符数 ÷ 2 | "我爱你" = 3字符 ÷ 2 = 1.5词 |
| 日语 | 字符数 ÷ 2.5 | "ありがとう" = 5字符 ÷ 2.5 = 2词 |
| 韩语 | 字符数 ÷ 2 | "감사합니다" = 5字符 ÷ 2 = 2.5词 |

---

### 步骤2: 应用YouTube字幕上限

**目标**：单条字幕不会无限长，设置一个天花板

```
实际英文词数 = Min(英文等价单词数, 100)
```

**逻辑**：
- YouTube单条字幕通常不超过100个英文单词
- 如果换算出200个英文词，也按100词算
- 防止极端长文本浪费Token配额

**示例**：
- 英文等价单词数 = 150
- 实际英文词数 = Min(150, 100) = **100**

---

### 步骤3: 翻译成目标语言后的单词数

**目标**：英文翻译成目标语言，单词数会变化

```
目标语言单词数 = 实际英文词数 × 目标语言缩放比例
```

**示例1（英文 → 中文）**：
- 实际英文词数 = 100
- 中文缩放比例 = 0.5（表1查询）
- 目标语言单词数 = 100 × 0.5 = **50个中文词**

**示例2（英文 → 西班牙语）**：
- 实际英文词数 = 100
- 西班牙语缩放比例 = 1.15（表1查询）
- 目标语言单词数 = 100 × 1.15 = **115个西班牙语词**

---

### 步骤4: 单词数转换为Token数

**目标**：不同语言每个单词占用的Token数不同

```
基础Token数 = 目标语言单词数 × 该语言每个单词的平均Token数
```

**示例1（中文）**：
- 目标语言单词数 = 50个中文词
- 中文每词Token数 = 2.5（表2查询）
- 基础Token数 = 50 × 2.5 = **125 Token**

**示例2（印地语）**：
- 目标语言单词数 = 100个印地语词
- 印地语每词Token数 = 6.4（表2查询）
- 基础Token数 = 100 × 6.4 = **640 Token**

---

### 步骤5: 应用安全边际和上下限

**目标**：防止估算不准导致截断，同时不超过模型限制

```
步骤5a: 应用安全系数
安全Token = 基础Token × 1.5

步骤5b: 应用上下限保护
最终Token = Min(Max(安全Token, 200), 65536)
```

**三重保护机制**：
1. **安全系数1.5** - 50%冗余，防止估算误差
2. **下限200** - 短字幕保底，防止过小
3. **上限65536** - Gemini 2.5的硬性限制

**示例1（正常情况）**：
- 基础Token = 125
- 安全Token = 125 × 1.5 = 187.5
- 最终Token = Min(Max(187.5, 200), 65536) = **200**（触发下限）

**示例2（长字幕）**：
- 基础Token = 640
- 安全Token = 640 × 1.5 = 960
- 最终Token = Min(Max(960, 200), 65536) = **960**

**示例3（超长批次）**：
- 基础Token = 80000
- 安全Token = 80000 × 1.5 = 120000
- 最终Token = Min(Max(120000, 200), 65536) = **65536**（触发上限）

## 📐 完整计算公式总结

```
步骤1: 英文等价词数 = 源语言词数 ÷ 源语言缩放比例（表1）

步骤2: 限制词数 = Min(英文等价词数, 100)

步骤3: 目标语言词数 = 限制词数 × 目标语言缩放比例（表1）

步骤4: 基础Token = 目标语言词数 × 目标语言每词Token数（表2）

步骤5: 最终Token = Min(Max(基础Token × 1.5, 200), 65536)
        ↑            ↑                         ↑
      上限保护      下限保护                Gemini限制
```

## ⚙️ 技术实现要点

### 1. 未知语言的Fallback策略

如果遇到表1、表2中未定义的语言：

```typescript
// 缩放比例默认值
const TRANSLATION_WORD_RATIO_DEFAULT = 1.0;  // 假设与英文相当

// Token消耗默认值
const TOKENS_PER_WORD_DEFAULT = 3.0;  // 保守估计（中等偏高）
```

**逻辑**：宁可高估，不要低估，防止截断

---

### 2. 语言代码规范化

支持带地区后缀的语言代码：

```typescript
// 输入: 'zh-CN' → 查表: 先查'zh-CN'，找不到再查'zh'
const baseLang = langCode.split('-')[0];
const ratio = TRANSLATION_WORD_RATIO[langCode]
           || TRANSLATION_WORD_RATIO[baseLang]
           || TRANSLATION_WORD_RATIO_DEFAULT;
```

---

### 3. 模型上限适配

不同AI模型的maxOutputTokens上限不同：

| 模型 | maxOutputTokens上限 |
|------|-------------------|
| Gemini 1.5系列 | 8,192 |
| Gemini 2.5系列 | 65,536 |
| OpenAI GPT-4 | 4,096 - 16,384（视版本） |
| DeepSeek | 8,192 |

**实现**：
```typescript
const MODEL_MAX_OUTPUT = {
  'gemini-1.5-flash': 8192,
  'gemini-2.5-flash': 65536,
  'gpt-4': 4096,
  'deepseek-chat': 8192
};

// 应用模型上限
finalTokens = Math.min(estimatedTokens, MODEL_MAX_OUTPUT[modelName]);
```

### 4. 批量翻译的Token估算

如果一次翻译多条字幕（批量翻译）：

```typescript
// 方法1: 逐条估算后累加
const totalTokens = subtitles
  .map(text => estimateTokens(text, sourceLang, targetLang))
  .reduce((sum, tokens) => sum + tokens, 0);

// 方法2: 合并后统一估算（推荐，更准确）
const combinedText = subtitles.join('|SEP|');
const totalTokens = estimateTokens(combinedText, sourceLang, targetLang);
```

**推荐方法2**：因为批量翻译时，AI模型会在一个上下文中处理，更符合实际

## 📌 常见问题（FAQ）

### Q1: 为什么不直接用"输入Token × 目标语言倍数"？

**A**: 因为不同语言的Token消耗差异巨大。例如：
- 100个中文Token ≠ 100个英文Token（信息量不同）
- 需要先换算成"语义等价的英文单词数"作为中间基准

---

### Q2: 为什么单条字幕上限是100词？

**A**: 基于YouTube实际数据：
- 标准字幕：5-15词/行，单条2-5行 = 10-75词
- 长字幕：最多不超过100词
- 超过100词通常会被拆分成多条

---

### Q3: 表1和表2的数据准确吗？

**A**: 数据来源：
- **表1**：基于语言学研究和实际翻译经验估算
- **表2**：OpenAI官方公布数据 + 社区实测

**建议**：根据你的实际业务数据定期校准

---

### Q4: 安全系数1.5是否过于保守？

**A**: 1.5倍是经验值，原因：
- AI翻译长度有±20%波动
- 标点符号、特殊字符额外消耗
- 避免因1-2个Token差异被截断

**成本优化**：如果预算紧张，可调至1.3倍

---

### Q5: 如何处理混合语言的字幕？

**A**: 两种策略：
```typescript
// 策略1: 按主要语言估算（简单）
const mainLang = detectMainLanguage(text);  // 检测占比最高的语言
const tokens = estimateTokens(text, mainLang, targetLang);

// 策略2: 分段估算后累加（精确）
const segments = splitByLanguage(text);  // 按语言分段
const tokens = segments
  .map(seg => estimateTokens(seg.text, seg.lang, targetLang))
  .reduce((sum, t) => sum + t, 0);
```

**推荐**：策略1，因为混合语言字幕很少见
